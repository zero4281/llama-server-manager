+### Bug Report
+**Title:** `--update-llama` fast path fails to restart `llama-server`
+**Status:** Pending
+**Severity/Priority:** High
+**Dependencies:** None
+**Description:**
+When running `./llama-server-manager --update-llama` with valid `options.llama-cpp.os-architecture` and `options.llama-cpp.backend` in `config.json`, the program uses the "fast path" update. This path calls `_install_release_core` in `llama_updater.py`, which handles the download, extraction, and verification of the new `llama-server` binary, but it does not call `_restart_llama_server`. Consequently, while the binary is updated on disk, the currently running `llama-server` process is not stopped or restarted.
+
+In contrast, the interactive `--install-llama` path calls `install_release`, which correctly calls `_restart_llama_server` after a successful installation.
+
+**Verified Reproduction Workflow:**
+1. Configure `config.json` with `options.llama-cpp.os-architecture` (e.g. "Ubuntu-x64") and `options.llama-cpp.backend` (e.g. "cpu").
+2. Ensure a `llama-server` instance is running (PID recorded in `llama-server.pid`).
+3. Run `./llama-server-manager --update-llama`.
+4. Observe that the `llama-server` process (PID from step 2) remains running and the PID file remains unchanged after the "Installation complete!" message.
+5. The new binary is present on disk but the running process is stale.
+
+**Affected Components:**
+- `llama_updater.py` (`_install_release_core` function)
